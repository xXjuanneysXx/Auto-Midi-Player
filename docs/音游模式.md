# 音游模式（v1.1.0 新增）

跟奏窗口（`follow.py`）里多了第三种节奏：**音游模式**。练习模式是「你按对了才往下走」，
音游模式是**按原曲速度自己往下落**，你弹得怎么样它给你打分 —— 程序一个键都不发。

判定 / 计分 / 记录全在 `rhythm.py` 里，纯逻辑、不碰 Qt，命令行就能测；
界面（下落、倒计时、连击、判定牌）在 `follow.py` 的 `_tick_rhythm` / `_paint_rhythm`；
成绩窗口是 `main.py` 的 `RhythmResultWindow`。

## 一、怎么玩

1. 勾上「跟奏模式」（Ctrl+F2），「跟奏节奏」选 **音游模式**，按 F6 开始；
2. 先来 3、2、1 倒计时（这期间音符停在顶上不动，`RHYTHM_COUNTDOWN = 3.6` 秒，
   最后 0.6 秒显示 GO）；
3. 音符按原速落下，落到判定线上你要**同时**按下对应的琴键和鼠标键
   （音符的颜色 / 记号就是该按哪个鼠标键，跟原速跟奏一样）；
4. F7 暂停 / 继续，F8 停止。整首走完自动弹结算窗口。

原速 = 谱面本来的时值（不受「倍速」下拉框影响），但「音长」设置照旧生效 ——
长条多长就要按多久。

## 二、判定规则

| 档位 | 什么时候 | 记什么 |
| --- | --- | --- |
| PERFECT | 按下时机在判定窗内，且按住时长的相对误差 ≤ **10%** | 加分 + 连击 |
| GOOD | 同上，误差 ≤ **30%** | 加分 + 连击 |
| MISS · 差一点 | 按到了，但误差 > 30% | **给分**（比 GOOD 少），断连击；不算「错」 |
| MISS · 漏按 | 越过判定线 **150 毫秒**还没按，或者**下一个音已经开始弹了** | 不扣分，算「错」，断连击 |
| WRONG（按错键） | 琴键按对了，但升降调 / 半音（鼠标组合）不对 | 不扣分，算「错」，断连击 |

> **界面上不出现「不达标」这种词**（用户要求）：按到了但不够准的，显示上也叫 MISS。
> 内部还是分开记的（`plain` / `miss`），只是给玩家看的数字合在一起 ——
> `rhythm.Session.summary()['miss']` 就是①+②+③的总数。

* 「按住时长的相对误差」= `|按住时长 − 音长| / 音长`（`rhythm.relative_error`）。
  按住时长从「按下」算到「松开」，按下时刻早于音符本身时从音符开始时刻算起
  （抢拍按下去不算你多按了）。
* 判定窗：`[音符开始 − 0.25 秒, 音符开始 + 0.15 秒]`（`EARLY_WINDOW` / `LATE_LIMIT`）。
* 琴键和鼠标几乎同时按才算对，但**手指顺序反了不白扣**：键先按下去之后，
  还有 `COMBO_GRACE = 0.09` 秒的宽容等鼠标组合对上（见 `_armed`）。
* miss 和 wrong **分开统计、分开显示**（用户要求区分「漏按」和「按错键」）。

**只按最靠前的那个音判定**：判定永远盯着「下一个还没判的音」。按错列 =
那个音记 wrong（不让它变成「既按错又漏按」两次惩罚）。

## 三、计分

```
PERFECT +100 ・ GOOD +60 ・ MISS（差一点）+30
MISS（漏按）/ WRONG：0 分 —— 不扣分，一首都弹错也不会负分
连击（PERFECT / GOOD 连续）从第 3 个起，每多连一个多 +5，不封顶
```

例：4 个全 PERFECT = 400 + 5 + 10 = **415** 分（第 3 连 +5、第 4 连 +10）。
分数**不会低于 0**：只有「差一点」和「漏按 / 按错」三种情况的极端成绩就是 0 分，
不会出现负数（这是用户明确要求的，扣分太难受）。

## 四、星星

一共 5 颗：

* 一次都没按错 / 漏按 → **5 颗黄星**；
* 有错 → `5 − ceil(错数 / 5)`，最低 1 颗（错 1~5 个 = 4 星，6~10 个 = 3 星，……）；
  「错数」= WRONG + 漏按 MISS；**「差一点」那种不算错**（它已经给了分）。
* 黄星里能升级成**炫彩星**（彩带渐变的五角星）的：
  * PERFECT 占比 ≥ 90% → 1 颗；
  * 最长连击 ≥ 总音符数的 1/3 → 1 颗；
  * PERFECT 占比 ≥ 70% 或最长连击 ≥ 总音符数的 2/3 → 1 颗；
  * 一个不漏而且全是 PERFECT → 直接 5 颗全炫彩。

## 五、成绩记录

### 本机

`%LOCALAPPDATA%\AutoPlay\rhythm_records.json`，按曲子分开存，一首歌留分数最高的 **50** 条：

```json
{ "鸟之诗.mid": [ {"format": "autoplay-rhythm-score", "name": "某某", "score": 3820,
                   "stars": 5, "rainbow": 3, "perfect": 36, "good": 4, "plain": 0,
                   "wrong": 0, "miss": 0, "max_combo": 40, "notes": 40,
                   "app_version": "1.1.0", "time": "2026-10-06 17:40:00"} ] }
```

存之前要填名字（最多 12 个字，`rhythm.NAME_LIMIT`）。名字框每次都空着，自己写。

### 联网

曲库仓库（默认 Gitee `juanneys/midi-music`）的 `音游记录/` 目录下：

```
音游记录/<曲名>/<时间>-<4 位随机>.json      # 一条成绩一个文件
```

**为什么一条一个文件**：`contents` 接口写文件要带 sha（改动前先读一次），
所有人往同一个大 json 里写必然互相顶掉。一条一个文件谁传谁的，不会撞车。

代价是读的时候要「先列目录、再一个个读」，所以：

* 只读最新的 `ONLINE_FETCH_LIMIT = 30` 个文件（文件名前面就是时间，倒着取）；
* 读和传都在后台线程，界面只显示「正在读联网成绩…」；
* 拉回来的成绩缓存进窗口，不反复读。

**曲子的身份 = 文件名**（国内曲库和 GitHub 曲库同名，两边能合起来比；重名的不比较）。

**门禁：只有联网曲库里的曲子才能上传成绩**（`rhythm.in_library()`：拿本机文件名跟
曲库索引里的 `file` 逐条比，大小写不敏感）。本机自己转的 mp3、自己做的曲子 ——
音游照玩、本机记录照存，但「上传到联网记录」按钮是灰的，并写着怎么才能上榜：
「联网曲库」→「上传 / 整理曲库…」把这首传上去，回来点「刷新排行榜」。
理由：不然 `音游记录/` 会堆一堆别人根本下不到的曲子，榜单也没法比。
连不上、确认不了的时候同样是灰的，提示「请检查网络连接」。

**联网读不到的时候**（没网 / 连不上 Gitee）：窗口只提示一句
「没读到联网成绩 —— 请检查网络连接」，**不会自己反复重试**（以前会疯狂重试，
把机器拖死）；好了点「**刷新排行榜**」手动重读一次就行。本机记录一直能看能存。

**名字不预填**：每次开结算窗口，名字框都是空的，自己写（最多 12 个字）。
只有「存到本机」和「上传到联网记录」需要名字，光看分数不用写。

**风险（用户知情）**：程序里内置了写入用的令牌，谁都能从 exe 里抠出来改仓库内容 ——
这跟错误上报是同一个令牌、同一套通道。所以：上传要用户自己点、名字限长、没有删除接口
（只能去仓库里手动删）。

### 配置（可远程改）

仓库根目录 `rhythm.json`（程序启动时后台拉一份，缓存到
`%LOCALAPPDATA%\AutoPlay\rhythm_remote.json`）：

```json
{ "format": "autoplay-rhythm", "enabled": true, "site": "gitee",
  "owner": "juanneys", "repo": "midi-music", "branch": "master", "dir": "音游记录" }
```

换仓库 / 换目录不用重新打包程序（跟 `error_report.json` 一个路子）。
`library.is_meta_path()` 把 `音游记录/` 和 `快速上手/` 都划成元文件，不会被当成曲子解析。

## 六、判定图标

`judgeicons.py` **用代码画**（跟 `uiicons.py` 一个规矩：不占打包体积、任意 DPI 清晰、
颜色跟主题走）。风格是新拟态，跟程序现在的 UI 一致：

* 一块软边胶囊牌 + 外阴影 + 上沿高光 + 判定色内描边 + 一层判定色光晕；
* 文字**斜体、微微上翘**（不是方方正正那种），填色是渐变：
  PERFECT 直接用**彩虹**渐变，还在牌底下压一条彩虹细带；其它档用自己的色从亮填到更亮；
* 牌左边挂一个小装饰：PERFECT / COMBO 五角星、GOOD 四角闪光、WRONG 闪电、MISS 斜杠；
* 文字走「先描一圈深色轮廓，再填渐变色」——HUD 上缩到 26 像素也看得清；
* 判定色沿用自己的色板：PERFECT 青 `#3fd8e8`、GOOD 绿 `#5fd18b`、MISS 红 `#f08a8a`、
  按错键橙 `#ffb347`、连击金 `#ffc247`；
* `judgeicons.star(size, rainbow=True)` 画星星：黄星 `#ffc247`，炫彩星是六段彩虹渐变。

想换风格只改这一个文件：`badge()` 里那几行（底色渐变 / 高光 / 描边）就是全部。
`docs\音游图标方案\预览.png` 里还留着当初给用户挑的三套方案（霓虹描边 / 新拟态 / 街机像素），
现在用的是**方案 B 新拟态**。

## 七、想调参数改哪儿

| 想改什么 | 改哪儿 |
| --- | --- |
| PERFECT / GOOD 的容差 | `rhythm.HOLD_PERFECT` / `HOLD_GOOD` |
| 判定窗口、漏按判定 | `follow.RHYTHM_COUNTDOWN`（倒计时）、`rhythm.EARLY_WINDOW` / `LATE_LIMIT` |
| 键与鼠标的宽容时间 | `follow.COMBO_GRACE` |
| 基础分、连击加分 | `rhythm.BASE_SCORE` / `COMBO_STEP` / `COMBO_FROM` |
| 星级门槛 | `rhythm.stars()` / `rhythm.rainbow()` |
| 一首歌留几条本机记录 | `rhythm.MAX_LOCAL` |
| 联网一次读几个文件 | `rhythm.ONLINE_FETCH_LIMIT` |
| 名字长度 | `rhythm.NAME_LIMIT` |
| 判定图标长相 | `judgeicons.badge()` / `judgeicons.star()` |
