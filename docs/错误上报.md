# 出错自动上报（v1.0.6 起）

用户机器上崩了，作者看不到现场 —— 这个功能就是干这个的：程序没接住的异常会自动
打包成一份 json，传到曲库仓库（默认 Gitee `juanneys/midi-music`）的 `错误报告/`
目录里，打开仓库就能看。

## 传什么 / 不传什么

| 传 | 不传 |
| --- | --- |
| 程序版本、完全版 / 精简版 | 用户名 |
| Python 版本、Windows 版本、是不是管理员 | 完整路径（`C:\Users\某某\…` 换成 `<path>`，家目录换成 `<home>`） |
| 错误代码（`AP-XXXXXX`，内容哈希前 6 位） | 磁盘序列号 / 机器码之类 |
| 异常类型 + 调用栈（最多 60 行） | 歌名（能识别成音频 / midi / 工程文件名的也会一并换掉） |
| **安装目录 / 调用栈里的路径有没有中文**（布尔值） | |

``路径里有没有中文`` 这个信号专门留着：很多「别人能用我不能用」的问题就是装在
`D:\音乐软件\` 这种带中文的目录下引起的，但它又不暴露路径本身。

## 开关

* 程序「设置」里的 **出错自动上报** 勾选框，**默认开着**，取消勾选就不传；
* 用户自己的选择写在 `%LOCALAPPDATA%\AutoPlay\error_report_local.json`，
  优先级最高（覆盖仓库里的配置）；
* 一次运行最多传 3 条，同一条错误只传一次 —— 免得死循环崩溃把仓库刷屏；
* 连不上 / 没令牌就安静地算了，不影响程序。

## 配置文件

仓库根目录的 `error_report.json`（程序启动后跟公告 / 版本信息一起在后台拉，
拉到就缓存到 `%LOCALAPPDATA%\AutoPlay\error_report_remote.json`）：

```json
{
  "format": "autoplay-error-report",
  "enabled": true,
  "site": "gitee",
  "owner": "juanneys",
  "repo": "midi-music",
  "branch": "master",
  "dir": "错误报告"
}
```

| 字段 | 意思 |
| --- | --- |
| `enabled` | 全局开关（用户本机没设置过时按它） |
| `site` / `owner` / `repo` / `branch` | 报告传到哪个仓库 |
| `dir` | 传到仓库里的哪个目录 |

改这个文件不用重新打包，下次启动就生效（跟 `notice.json` / `version.json` 一个路子）。

## 报告长什么样

```json
{
  "format": "autoplay-error-report",
  "code": "AP-0C29C6",
  "time": "2026-10-05 18:30:12",
  "app_version": "1.0.6",
  "edition": "full",
  "python": "3.12.8",
  "os": "Windows 10 (19045)",
  "admin": true,
  "where": "程序",
  "install_path_chinese": false,
  "path_chinese": true,
  "error": "Traceback (most recent call last):\n  File \"<path>\", line 1, in <module>\nValueError: 读不了 <path> 失败"
}
```

## 为什么不传 Issues

用户明确要求：**只在仓库里新建 json**，不提 issue、不发邮件 —— 免得给仓库制造
通知噪音。程序走的是 Gitee / GitHub 的 contents API（`library.put_file`），
跟传曲子是同一套通道和同一个内置令牌。

## 别把它当曲子

`错误报告/` 里的 json 不是曲子。`library.parse_index()` 里加了
`is_meta_path()` 兜底：`library.json` / `notice.json` / `version.json` /
`update.json` / `themes.json` / `error_report.json` 以及 `错误报告/` 目录下的东西
一律不当曲子解析。
