# 最小化的两个坑：屏幕残留 & 任务栏点不回来

> 这一篇讲的是 v1.0.4 里修掉的两个 bug，以及**为什么会这样**。
> 它们都不是「代码写错了」，而是 Windows 窗口管理器（DWM / shell）跟 Qt
> 之间一些没写在明面上的规则导致的。把这几个规则弄清楚，「浮层类窗口」以后就不会再踩。
>
> 涉及代码都在 `main.py`：`minimize_window()` / `_enter_minimized_visual_state()` /
> `_restore_after_minimize()` / `_apply_window_mode()`，以及模块级的
> `set_no_activate()` / `set_taskbar_window()` / `show_no_activate()`。

---

## 一、先搞清楚这个窗口是怎么造的

AutoPlay 默认是「浮层形态」（设置里的「游戏内覆盖」）：贴着游戏的一块小窗口，
点它不会把前台从游戏抢走。这个效果是靠一组 Qt 窗口标志 + 几个 Win32 扩展样式做出来的，
在 `_apply_window_mode()` 里：

```python
flags = Qt.WindowType.Window | Qt.WindowType.FramelessWindowHint
flags |= Qt.WindowType.WindowDoesNotAcceptFocus    # ← 关键，见下
flags |= Qt.WindowType.WindowStaysOnTopHint        # 永远压住游戏
self.setAttribute(Qt.WidgetAttribute.WA_ShowWithoutActivating, True)
self.setWindowOpacity(0.96)                        # ← 关键，见下
```

再加上 `set_no_activate(self, True)` 手动补一个 Win32 扩展样式 `WS_EX_NOACTIVATE`，
这样「点它、点它里面的按钮都不会抢焦点」，全屏游戏不会掉回桌面。

代价就是下面这两个 bug。先把这两件事记牢：

| 我们用的东西 | Windows 给窗口加的位 | 副作用 |
| --- | --- | --- |
| `WindowDoesNotAcceptFocus` / `set_no_activate()` | `WS_EX_NOACTIVATE` (0x08000000) | **窗口不进任务栏** |
| `setWindowOpacity(0.96)` | `WS_EX_LAYERED` (0x00080000) | 半透明合成，DWM 那片「画面」最小化时可能不被擦掉 |
| `WindowStaysOnTopHint` | `WS_EX_TOPMOST` (0x00000008) | 一直压在最上层 |

## 二、Bug 1：最小化以后，屏幕上留着一条残影

### 现象

点「—」最小化，窗口缩下去了，但屏幕左边留下一条约 470×40 的横条，
半透明、上面还写着「MIDI 简谱自动演奏」——就是主窗口的标题行。
点别的地方不一定擦得掉，任务栏里也找不到这个程序，用户以为程序没了。

### 怎么查的（这段方法可以留着以后用）

没法靠猜，直接上「真窗口 + 截屏 + 像素比对」：

1. 用真实 `MainWindow` 跑起来，最小化前后各截一张全屏图；
2. 把可疑区域裁出来放大看 —— 残影一眼就能看到（它不是长在窗口那块位置的！）；
3. 量一个数：残影区域的平均亮度。窗口在的时候是 172.5，老做法最小化之后是 165.4
   （暗了 7.1），修好之后又是 172.5（差 0.0）。**用数字判断，别用眼睛。**

顺带还把任务栏那一行单独截出来做像素 diff，用来判断「按钮到底有没有出现」。

### 真正的原因（三层叠在一起）

**① 最要命的一层：浮层窗口从一开始就没有任务栏按钮。**

`WS_EX_NOACTIVATE` 的官方说明里有一句很容易漏掉的话：

> The window does not appear on the taskbar **by default**.
> To force the window to appear on the taskbar, use the `WS_EX_APPWINDOW` style.

也就是说，**带这个位的窗口在创建的那一刻就被 shell 判成「不进任务栏」**。
最小化的时候，Windows 会做一个「窗口缩到任务栏按钮上」的飞行动画——
这个窗口没有那个落点，动画就崩了，Windows 干脆把窗口**最后那幅画面**丢在桌面上不管了。

而且它丢的位置跟窗口当前的坐标**没有关系**（实测窗口在 `(890, 346)`，残影出现在 `x 0..470`）。
所以第一版修复「把窗口原来那块区域标脏重画」根本没用到点上。

还有一个更坑的地方：**事后补 `WS_EX_APPWINDOW` 也补不回来。**
我实测过三种状态（显示中 / 最小化 / 完全隐藏），任务栏那一行像素**逐字节完全一样**，
UI Automation 里也始终找不到这个窗口的按钮。结论：任务栏按钮的有无，
是在**窗口创建时**定死的，`SetWindowLong` 改样式 + `SetWindowPos(SWP_FRAMECHANGED)`
都不会让 shell 回头再算一遍。

**② 半透明那一层（`WS_EX_LAYERED`）。**

`setWindowOpacity(0.96)` 会让窗口变成 layered window，画面由 DWM 单独合成。
这种窗口最小化时，系统不保证把留在桌面上的那一层擦掉，是第二处残影来源。
（顺手说：`setWindowOpacity(1.0)` 会把 `WS_EX_LAYERED` 摘掉，这是把它消掉的办法。）

**③ 右上角那个进度浮窗。**

「已就绪 / 演奏中 12/345」那个小窗是**独立的置顶窗口**（`Overlay`，父窗口是 `None`，
`Qt.Tool`）。主窗口缩进任务栏之后，它照样待在桌面上——这本身就是一块「残留」。

### 最后怎么修的

`_enter_minimized_visual_state()` 里按顺序做：

```
1. 记下「主窗口 + 浮窗」一起占的屏幕区域（_capture_ghost_rect）
2. 把进度浮窗收起来（正在演奏时不动：那会儿它是唯一能看进度的地方）
3. hide() 藏起来，再 _apply_window_mode(False) —— 真的把窗口切成普通窗口
      ↳ 这一步会重建原生窗口，新窗口创建时没有 WS_EX_NOACTIVATE，任务栏这才认它
4. setWindowOpacity(1.0) 拆掉 layered
5. set_taskbar_window(self, True) 补 WS_EX_APPWINDOW（双保险）
6. showMinimized()；再用 Win32 ShowWindow(SW_MINIMIZE) 兜一刀
      ↳ Qt 在「窗口刚重建过」的时候不一定真缩下去，实测 IsIconic=0，所以要补
7. 60ms 后把第 1 步记下的区域标脏，让系统重画一遍（RedrawWindow）
```

还原的时候反过来：`_restore_after_minimize()` 按用户原来的设置
（`settings` 里的 `cover_mode`）`_apply_window_mode(True/False)` 切回去，
再把不透明度补回 0.96、把浮窗补回「已就绪」。

因为「换形态」本身会触发一串窗口状态事件，中间那几次不能被当成「用户真的最小化/还原了」，
所以加了两个标记：`_minimize_busy`（换形态过程中 `changeEvent` 直接返回）和
`_overlay_suspended_for_minimize`（记着「这次最小化把形态换过了，还原要换回去」）。

### 修完的效果（实测）

| 看什么 | 修之前 | 修之后 |
| --- | --- | --- |
| 残影区域亮度（基线 172.5） | 165.4（暗 7.1） | 172.5（差 **0.0**） |
| 最小化时任务栏 | 没有按钮 | 有按钮（像素 diff **16175**） |
| 窗口完全隐藏后 | —— | 按钮消失（diff 又回到 16175，方向相反） |

## 三、Bug 2：任务栏图标点不回来

### 现象

最小化没问题了、任务栏也有图标了，但**点那个图标窗口不回来**（屏幕上什么都没有）。

### 原因：Qt 认为窗口是「藏着」的，所以不画

`_apply_window_mode()` 在 `setWindowFlags(...)` 之后要把窗口重新显示出来。
`setWindowFlags` 会**销毁并重建原生窗口**，同时 Qt 会把 widget 标成「隐藏」。
原来的代码是这么显示的：

```python
if self.overlay_active:
    show_no_activate(self)      # ← 里面是 Win32 的 ShowWindow(SW_SHOWNOACTIVATE)
else:
    self.show()
```

问题就在浮层那一支：**`show_no_activate()` 直接调 Win32 的 `ShowWindow`，
绕过了 Qt 的 `show()`**。结果是：

* Windows 那边：窗口显示出来了（`IsIconic=0`、`IsWindowVisible=1`）；
* Qt 那边：`QWidget::isVisible()` 还是 **False**（`WA_WState_Visible` 没被置起来），
  Qt 认为这个 widget 不需要画 → **一个像素都不画**。

所以从任务栏点回来的时候，`SC_RESTORE` → 我们的 `_restore_after_minimize()` →
`_apply_window_mode(True)` → `show_no_activate()` → 窗口在系统层面「回来了」，
在 Qt 层面却是个「看不见的隐藏窗口」。用户看到的就是「点了没反应」。

实测那一下的状态长这样（`Qt.isVisible` 就是 False）：

```
点任务栏后  IsIconic=0  IsVisibleOS=1  Qt.isVisible=False  Qt.isMinimized=False  overlay_active=True
```

### 怎么修的

**`setWindowFlags` 之后，一定要走 Qt 自己的 `show()`**，不能只靠 Win32 的 `ShowWindow`：

```python
if visible:                    # setWindowFlags 会把窗口藏起来，得重新显示
    self.show()                # ← 让 Qt 走完自己的显示流程（才会画）
    if self.overlay_active:
        show_no_activate(self) # ← 再补一刀：置顶 + 不激活
    self.move(pos)
```

浮层形态怕 `show()` 抢游戏前台？不会：前面已经设了
`WA_ShowWithoutActivating`，Qt 在这种情况下内部用的就是
`ShowWindow(SW_SHOWNOACTIVATE)`——**既让 Qt 认了，又不抢焦点**。

### 修完的效果（实测）

```
点任务栏后  IsIconic=0  IsVisibleOS=1  Qt.isVisible=True   Qt.isMinimized=False  overlay_active=True
浮窗可见 = True state = ready opacity = 0.96
```

界面完整回来了（含右上角「已就绪 0 / 437」浮窗），位置也没跑。

## 四、顺手记下来的几条 Win32 / Qt 常识

* **`WS_EX_NOACTIVATE` 会让窗口不进任务栏**，而且**必须在窗口创建时**就没有它；
  事后补 `WS_EX_APPWINDOW` 不管用。要「平时不进任务栏、最小化时进」，只能**重建窗口**
  （`setWindowFlags`）或者干脆别用 `NOACTIVATE`。
* 判断任务栏有没有按钮，最靠谱的办法是**截图 + 像素 diff**（这次就是靠它定案的）；
  UI Automation 枚举任务栏按钮在这台机器上给出的结果不全，不能当准。
* `setWindowOpacity(1.0)` 会摘掉 `WS_EX_LAYERED`；`< 1.0` 会加上。
* 「点击任务栏按钮」= 系统给窗口发 `WM_SYSCOMMAND` + `SC_RESTORE`（再 `ShowWindow(SW_RESTORE)`）。
  想复现这个动作，PostMessage 这两条就够了：
  ```python
  u32.PostMessageW(hwnd, 0x0112, 0xF120, 0)   # WM_SYSCOMMAND, SC_RESTORE
  u32.ShowWindow(hwnd, 9)                     # SW_RESTORE
  ```
* 窗口缩下去之后 `frameGeometry()` 在 Windows 上会变成 `(-32000, -32000)` 这种占位坐标，
  要拿原来位置得用 `normalGeometry()`。
* Qt 的窗口状态和系统的不一定同步：光看 `IsIconic()` 不够，
  必要时两边都查（这次就是「系统说可见、Qt 说隐藏」）。

## 五、以后加「浮层」类功能时的检查清单

1. 这个窗口要不要出现在任务栏？要的话，**创建时就别带 `WS_EX_NOACTIVATE`**
   （或者单独造一个普通窗口专门用来最小化）。
2. 半透明（`setWindowOpacity < 1`）的窗口最小化前，先 `setWindowOpacity(1.0)`。
3. 「独立的置顶小窗」（比如进度浮窗）要跟着主窗口一起收，不然就是残留。
4. 改过 `setWindowFlags` 之后，**一定要用 Qt 的 `show()`**，别只用 Win32 的 `ShowWindow`。
5. 改完别只看「窗口回来了没」，还要看**画出来没有**（`isVisible()` / 截屏）。
