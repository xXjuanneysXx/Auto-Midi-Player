# 在线安装程序（AutoPlay）—— 设计与实现

> **现状：v1.1.0 起有了，能用。**
>
> * 安装程序本体：`installer.py` —— 同一份源码，两种用法（离线 / 在线）
> * 切片 + 写清单：`make_parts.py`
> * 传切片到 Gitee Releases：`上传分片到Gitee.py`
> * 出在线安装程序 exe：`python -X utf8 make_installer.py online`
>
> 起因：有用户反馈**百度网盘下载完整安装包太慢**（完全版 221 MB）。在线安装程序只有
> **46 MB**，双击就能开始装，程序本体它自己去网上分批取。

---

## 一、一共三样东西

| 东西 | 多大 | 放哪儿 | 谁生成 |
| --- | --- | --- | --- |
| **在线安装程序** `AutoPlay 在线安装程序 vX.Y.Z.exe` | 46 MB | 发给用户（网盘 / GitHub Release 都行） | `make_installer.py online` |
| **清单** `payload.json` | 2 KB | 曲库仓库**根目录**（跟 `version.json` 放一起） | `make_parts.py` |
| **切片** `AutoPlay-full-1.1.0.zip.001` … | 每片 32 MB | Gitee Releases 的附件 | `make_parts.py` 切、`上传分片到Gitee.py` 传 |

为什么切片放 Gitee **Releases**、而不是仓库里：仓库里放 235 MB 的二进制会把 git 仓库撑坏
（每次提交都留一份），Releases 的附件是独立的存储，而且**单附件上限 100 MB** ——
所以每片切 32 MB（坏了只用重下 32 MB），完全版 6 片、精简版 2 片。

为什么清单走 Gitee **raw 直链**：实测这个仓库的 raw 能正常读中文 json（`notice.json`
就是这么读的），不需要令牌；加时间戳是为了躲 CDN 缓存（跟 `notice.py` 的做法一致）。

## 二、用户看到什么

```text
双击 AutoPlay 在线安装程序 v1.1.0.exe
        │
        │ 启动时看一眼「自己尾巴上有没有挂 payload」
        │   ├─ 有  → 离线安装（老路子，直接解压身上那份）
        │   └─ 没有 → 在线安装（走下面这条）
        ▼
   拉 payload.json（拉不到就提示，可以点「开始安装」再试一次）
        │
        ▼
   界面上选：安装版本（完全版 / 精简版）· 安装目录 · 快捷方式 · 装完运行
        │
        ▼
   按清单下切片：32 MB 一片，断点续传 + sha256 校验 + 失败换源重试 3 次
        │
        ▼
   PartsReader：把几片拼成「一个能随机读的 zip 流」（不落地大 zip）
        │
        ▼
   流式解压到安装目录  ←── 跟离线安装**走的是同一段代码**
        │
        ▼
   写说明.txt / 建快捷方式 / 写 uninstall.json / 注册到「应用和功能」
```

界面上「要下载 175.4 MB（6 片）· 安装后约 419.1 MB · 这个盘还剩 3.3 GB」这一行，
就是在清单拉回来之后算的（`install_size` 是清单里的字段）。

## 三、清单 `payload.json` 长什么样

```json
{
  "format": "autoplay-payload",
  "version": 1,
  "app_version": "1.1.0",
  "chunk_size": 33554432,
  "mirrors": [],
  "editions": {
    "full": {
      "label": "完全版",
      "zip": "payload-full.zip",
      "size": 183896373,          // 切片加起来的大小（要下多少）
      "install_size": 439479216,  // 解压后大概占多少磁盘
      "sha256": "9043a9…",        // 整包 sha256（对不上说明有片坏了）
      "parts": [
        {"name": "AutoPlay-full-1.1.0.zip.001", "size": 33554432, "sha256": "f059fa…"},
        {"name": "AutoPlay-full-1.1.0.zip.002", "size": 33554432, "sha256": "f21b9d…"}
      ],
      "base_urls": ["https://gitee.com/juanneys/midi-music/releases/download/v1.1.0"]
    },
    "lite": { "…": "同上" }
  }
}
```

真正下载时拼出来的地址是 `base_urls[0] + "/" + parts[i].name`，也就是
`https://gitee.com/juanneys/midi-music/releases/download/v1.1.0/AutoPlay-full-1.1.0.zip.001`。

`mirrors` 是**备用源**：以后想在别处也放一份切片（比如另一个仓库、另一家对象存储），
把前缀地址加进这个数组就行，安装程序会挨个试 —— 现在留空。

也可以临时换地址测试（不用重新打包）：

```powershell
$env:AUTOPLAY_PAYLOAD_INDEX = 'http://127.0.0.1:8000/payload.json'
.\发布\AutoPlay` 在线安装程序` v1.1.0.exe
```

## 四、断点续传 / 校验是怎么做的

下载目录：`%LOCALAPPDATA%\AutoPlay\下载缓存\<版本>`，**装完不删**（下次装、或者换版本接着用）。

每一片：

```text
本地已经有这个文件？
  ├─ 大小刚好、sha256 也对        → 跳过（重开安装程序接着下，不会重下）
  ├─ 大小不够（上次下到一半）      → 带 Range: bytes=<已有字节>- 接着下
  │                                 服务器不认 Range（回 200）就把多给的前半截丢掉，
  │                                 行为上跟 206 一样
  └─ 大小比清单写的还大            → 删掉重下

下完 → 大小对不对 → sha256 对不对
  ├─ 都对 → 留着
  └─ 不对 → 删掉，算这次失败

某一片失败 → 换下一个地址 / 重试，一共 3 次 → 还不行就报错：
  「可以重开这个安装程序接着下（已经下好的片会跳过），或者改用百度网盘那份完整安装包」
```

几个数（都在 `installer.py` 顶部）：

| 常量 | 值 | 意思 |
| --- | --- | --- |
| `NET_TIMEOUT` | 20 秒 | 单次请求读不到数据就断，别挂在那儿（midi/切片都是小文件） |
| `NET_RETRIES` | 3 | 一片最多试 3 次，每次换一个 `base_urls` / `mirrors` 里的地址 |
| 读块 | 256 KB | 边下边报进度，界面上能看到 MB/s 和「还剩约几分几秒」 |

进度条是**下载 + 解压合成一条**的：`总进度 = 下载字节 + install_size`，
所以从「正在下载第 3/6 片」到「正在安装：xxx.dll」是接着往前走的，不会跳回去。

## 五、发版时怎么做（顺序别弄反）

```text
① python -X utf8 build_no_relay.py            # 打两个完整安装包（含 payload）
② python -X utf8 make_installer.py online     # 出「在线安装程序 vX.Y.Z.exe」（46 MB）
③ python -X utf8 make_parts.py                # 切片到 发布\分片\ + 写 曲库索引\payload.json
④ python -X utf8 上传分片到Gitee.py --manifest # 传切片到 Gitee Releases + 发 payload.json
⑤ 手动：两个完整安装包 / 在线安装程序 发网盘、GitHub Release
```

要点：

* **先传切片，再发在线安装程序**。反过来的话，先拿到在线安装程序的用户一点「开始安装」
  就 404。
* Gitee 上没有 `vX.Y.Z` 这个 Release 时，第 ④ 步会**自己建一个**（tag 就是 `--tag`，
  默认 `v` + 清单里的版本号）。
* 第 ④ 步可以重复跑：**同名同大小的附件会跳过**，传一半断了接着跑就行。
* `payload.json` 要同时发到 **Gitee 和 GitHub** 两个曲库仓库 —— `--manifest` 就是干这个的。
* 在线安装程序**跟版本绑**：v1.1.0 的在线安装程序读 v1.1.0 的清单。清单里没有的版本
  （比如清单已经更新成 1.1.1、你还在跑 1.1.0 的在线安装程序）会提示「这份清单里没有
  这个版本」，让人重新下载最新的在线安装程序 —— 不会装出一个四不像。

## 六、本地怎么测（不发任何东西到网上）

正式发版前想先试试，不用把 235 MB 的切片先传到 Gitee —— 项目里带了一个小工具：

```powershell
python -X utf8 测试在线安装.py
```

它做三件事：

1. 读 `曲库索引\payload.json`，把每个版本的下载地址临时改成 `http://127.0.0.1:<端口>`；
2. 起一个只读的本地 HTTP 服务：`/payload.json` 给改过的清单，其它路径给 `发布\分片\` 里的片；
3. 设好 `AUTOPLAY_PAYLOAD_INDEX`，把 `发布\AutoPlay 在线安装程序 v1.1.0.exe` 打开。

接下来就跟真实用户拿到的一样了：选版本 → 选目录 → 点「开始安装」→ 看它下载 / 校验 / 解压 /
建快捷方式。想验证**断点续传**：下到一半把窗口关掉，再跑一遍 —— 下完的片会打印
「第 N/M 片已经下过了，跳过」，没下完的片接着下。

测试留下的东西：装出来的程序在界面上选的目录里（默认 `%LOCALAPPDATA%\AutoPlay`），
切片在 `%LOCALAPPDATA%\AutoPlay\下载缓存\<版本>`，不想要就把这两个删掉。

`--no-launch` 只起服务（自己开 exe / 想用 curl 试也行），`--port` 换端口，
`--exe` 指定要打开哪个安装程序（比如用 `dist_installer\AutoPlay-安装程序.exe` 测源码改动）。

## 七、常见问题

**问：清单拉不到怎么办？**
界面会写「暂时拉不到在线安装清单…点『开始安装』会再试一次；实在连不上就改用百度网盘那份
完整安装包」，并且把每个地址的失败原因列出来（HTTP 码 / 超时）。点「开始安装」会重新拉。

**问：装到一半关了 / 断网了？**
重开安装程序接着装。已经下完的片会跳过，下到一半的片带 Range 接着下。

**问：我换了版本要重下吗？**
完全版和精简版是两个目录（`下载缓存\full`、`下载缓存\lite`），互不干扰。
同一个版本重装不用重下。

**问：下载缓存占多大，能删吗？**
完全版约 175 MB、精简版约 58 MB（在 `%LOCALAPPDATA%\AutoPlay\下载缓存`）。
装完就删掉也没事 —— 下次装会重新下。卸载程序**不会**动这个目录（跟设置、录制一样，
留在那儿方便重装）。

**问：在线安装跟「增量更新」是什么关系？**
两码事，各管各的：

| | 增量更新 | 在线安装 |
| --- | --- | --- |
| 解决什么 | **已经装了**的旧版 → 新版（只下变了的文件，几十 MB） | **还没装**：完整安装包太大下不动 → 用 46 MB 的小程序分批下 |
| 谁在用 | 程序里的「更新」按钮 + `AutoPlayUpdater.exe` | 安装程序 + `payload.json` + 切片 |
| 单次下载量 | 20~35 MB（常态） | 完全版 175 MB / 精简版 58 MB（但分片、可断） |
| 文档 | `docs\增量更新设计.md` | 这篇 |

**问：以后能不能更快？**
几个方向，都还没做：

1. `mirrors` 里加第二个源（比如 GitHub Release 也放一份切片），国内 Gitee 抽风时自动切；
2. 几片**同时下**（现在是挨个下，一片 32 MB，串行慢的时候能干等）；
3. 缓存按「整包 sha256」存而不是按版本号存 —— 版本之间没改多少时可以复用一部分片
   （现在换版本要整包重下）。
