# 上传中转：让用户能传曲子，而安装包里不带令牌

## 这是干嘛的

往 GitHub 曲库仓库写文件需要**令牌**。以前的版本把令牌直接打进安装包 ——
谁都能从 exe 里把它抠出来，拿它删你曲库里的文件，GitHub 的密钥扫描还会主动
把公开仓库里的令牌**自动吊销**。

中转把这件事挪到服务器上：

```text
你的程序  ──POST 一首 midi──▶  中转（Worker，令牌存在它身上）  ──PUT──▶  GitHub 仓库
                                    │
                                    └─ 顺便重排 library.json
```

* 安装包里**一行令牌都没有**；
* 用你软件的人**什么都不用填**，打开程序就能传（体验跟内置令牌一模一样）；
* 要换令牌、要止损，改服务器上的一个变量就行 —— 不用重新打包，不用惊动用户；
* 顺手能拦：只收 midi、限大小、限频率，别人拿不走你的仓库。

整套东西跑在 Cloudflare Workers 的**免费额度**里（每天 10 万次请求，一个人用
连零头都不到的）。十分钟能搭完。

> 不想用 Cloudflare 也行：任何能跑 HTTP 的地方都可以（Deno Deploy、Vercel、
> 自己的小服务器…），接口就三个路由，照着 `worker.js` 改写成别的语言也不难。

---

## 第 1 步：造一个只干这一件事的令牌

1. 打开 <https://github.com/settings/personal-access-tokens/new>
   （Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token）
2. **Token name**：`AutoPlay 上传中转`
3. **Expiration**：随你（90 天 / 1 年 / 自定义）。⏰ 到期前记得回来换一个，
   否则用户的「上传」会开始报错。
4. **Repository access** → **Only select repositories** → 只勾 `midi-music`
5. **Permissions** → **Repository permissions** → **Contents** → **Read and write**
   （别的都不用给）
6. Generate token → **把 `github_pat_…` 这串复制下来**（离开页面就再也看不到了）

⚠ 这串令牌**只填给 Cloudflare**，不要写进 `github_token_local.py`、不要提交、
不要发给别人。

---

## 第 2 步：建一个 Worker

1. 注册/登录 <https://dash.cloudflare.com> （免费邮箱注册即可，不用绑卡）
2. 左边 **Workers & Pages** → **Create** → **Workers** → **Start with Hello World**（模板无所谓）
3. 名字随便起，比如 `autoplay-library` → **Deploy**
4. 部署完点 **Edit code**（右上角），把编辑器里的示例代码**全部删掉**，
   粘贴本目录 `worker.js` 的全部内容
5. 右上角 **Deploy**（会问你保存，确认即可）

这时候你有了一个地址，形如：

```text
https://autoplay-library.你的账号.workers.dev
```

---

## 第 3 步：把令牌交给它

Worker 页面 → **Settings** → **Variables and Secrets** → **Add**：

| 变量名 | 类型 | 值 | 必填 |
| --- | --- | --- | --- |
| `GITHUB_TOKEN` | **Secret**（加密） | 第 1 步那串 `github_pat_…` | ✅ 必填 |
| `OWNER` | Text | `xXjuanneysXx` | 选填（默认就这个） |
| `REPO` | Text | `midi-music` | 选填（默认就这个） |
| `BRANCH` | Text | `main` | 选填（默认就这个） |
| `UPLOAD_KEY` | Secret | 随便一串你自己编的口令 | 选填，见下面 |
| `MAX_MB` | Text | `2` | 选填（单个文件上限，MB） |

加完点 **Deploy** 让它生效。

**`UPLOAD_KEY` 是干嘛的：** 中转地址是公开的，谁都能往它发请求。不设口令的话，
有人可以拿它当免费网盘（虽然只收 midi、还限了频率）。设一个口令，并在程序那边
也配上同样的口令（下面第 5 步的 `--key`），就只剩带对口令的程序能用它；不设口令的话，知道地址的人都能往里传（虽然只收 midi、还限了频率）。
—— 但它**换不来你的 GitHub 令牌**：最多是别人也能往曲库传曲子，而你随时能在
Cloudflare 那边换个口令（或者加个域名防火墙），根本不用动仓库。

---

## 第 4 步：验证一下

浏览器打开 `https://你的地址.workers.dev/`，应该看到一句 json：

```json
{"ok": true, "told": "中转活着：xXjuanneysXx/midi-music@main，曲库里有 5 首", "bad": ""}
```

* 看到 **404 / 没有这个接口** → 代码没粘贴全，或者路径不是根路径；
* 看到 **GitHub 拒绝了（401/403）** → 令牌错了、过期了，或者没给 Contents 读写；
* 看到 **找不到仓库（404）** → `OWNER` / `REPO` / `BRANCH` 写错了；
* 看到 **上传口令不对** → 说明你设了 `UPLOAD_KEY`，浏览器访问没带口令，
  程序那边会带（用下面第 5 步的 `--key` 配）—— 这种情况属于正常。

---

## 第 5 步：写进程序并重新打包

在项目目录下：

```text
设置上传中转并重新打包.bat                  （双击，按提示粘贴地址）
python -X utf8 set_relay_url.py https://你的地址.workers.dev
python -X utf8 set_relay_url.py https://你的地址.workers.dev --key 你的口令
python -X utf8 set_relay_url.py https://你的地址.workers.dev --strip-token
```

脚本会先 `GET /health` 问一句（带上你给的口令），通了才往下走：**地址**写进 `relay_source.py`（这个文件进 git，所以只放地址），
**口令**写进 `relay_key_local.py`（**这个文件不进 git**，`.gitignore` 里已经挡好），然后重新打两个安装包（在「发布」文件夹里）。

**`--strip-token` 是重点。** 加上它，脚本会把 `github_token_local.py` 里的令牌
清空 —— 这样打出来的安装包**可以放心公开分发**：

* 用户打开就能传曲子（走中转）；
* 安装包里没有任何密钥，被抠也抠不出东西；
* 你想停掉上传，去 Cloudflare 换个令牌就行，用户无感。

不重新打包、只想本机先试：往 `%LOCALAPPDATA%\AutoPlay\library\relay.txt`
写一行地址，重启程序即可（口令写 `relay_key.txt`）。

## 常见问题

**连不上（超时）** —— `*.workers.dev` 在国内经常连不上。两个办法：

1. 给 Worker 绑一个自己的域名（Workers → 你的 Worker → Settings → Domains & Routes
   → Add → Custom Domain，域名不用备案也能用）；
2. 或者用 jsDelivr 那套思路：把中转换成一个能通的免费服务（Deno Deploy 的
   `*.deno.dev` 通常也能连）。

**「传得太勤了，歇一会儿再试」** —— 触发了我写的那道限流（同一 IP 每小时 30 次）。
自己的曲库不会碰到；真碰到了等一会儿就行。这个计数是尽力而为的（Cloudflare 会
同时跑多个实例，计数不共享），要严格限流得挂 KV，个人用不值当。

**想换仓库** —— 改 Cloudflare 里的 `OWNER` / `REPO` / `BRANCH` 就行，程序不用动。

**上传成功但歌单里没出现** —— 索引（`library.json`）刚提交，jsDelivr 那边有缓存，
等一两分钟；程序里点「刷新」也会重新拉。

**这个中转会不会挂** —— 免费额度每天 10 万次请求，一次上传算 3～4 次；
个人曲库一年也用不到一天的量。

## 想用命令行部署（可选）

装了 Node 的话，也可以在 `中转上传` 目录里用 wrangler：

```text
npm install -g wrangler
wrangler login
wrangler deploy worker.js --name autoplay-library
wrangler secret put GITHUB_TOKEN      （粘贴令牌）
```

`wrangler.toml` 里可以放 `OWNER` / `REPO` / `BRANCH` 这些非机密的 `[vars]`。

## 安全小结

| 方案 | 用户要不要填令牌 | 你的令牌安全吗 | 出事了怎么办 |
| --- | --- | --- | --- |
| 令牌内置在 exe 里 | 不用 | ❌ 解开 exe 就有，会被 GitHub 自动吊销 | 只能重新打包发新版，旧版全废 |
| 用户自己填令牌 | 要 | ✅ 安全 | 跟你的程序无关 |
| **上传中转（本方案）** | **不用** | ✅ 密钥在服务器上 | **改个变量，用户无感** |
