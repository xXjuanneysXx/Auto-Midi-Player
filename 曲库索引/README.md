# 曲库索引（**可选**，可传可不传）

## 这个仓库根目录一共放什么

曲库仓库（`gitee.com/juanneys/midi-music`，GitHub 上还有一个备用源）根目录除了曲子，
还放这几个**小 json**（程序联网读它们，改完不用重新发版）：

| 文件 | 干嘛的 | 谁生成 |
| --- | --- | --- |
| `library.json` | 联网曲库索引（有哪些曲子） | 程序里「上传 / 整理曲库…」，或者手写 |
| `version.json` | 版本信息：最新版本号 / 更新说明 / 几个按钮的链接 | 手改 |
| `notice.json` | 公告（一个数组，可以放多条） | 手改 |
| `update.json` | **增量更新清单**：每个文件的 sha256、差分包地址 | `python -X utf8 make_update.py …` 生成，**别手写** |
| `payload.json` | **在线安装清单**：程序本体切成几片、每片多大 / sha256 / 去哪儿下 | `python -X utf8 make_parts.py` 生成，**别手写** |
| `themes.json` | 线上配色（**预埋**，客户端现在只显示一条灰的「线上主题（未上线）」） | 手改（先留着空架子也行） |
| `manifests\*.json` | 每一版的文件清单，**留档用**（客户端不读，下次发版你自己要有一份基准） | `make_update.py --manifest-only` |
| `rhythm.json` | 音游成绩存哪个仓库 / 目录（**可选**，不写就用内置那套） | 手改 |
| `error_report.json` | 出错自动上报的开关 / 目标目录（**可选**） | 手改 |
| `快速上手\快速上手.md` | 「快速上手」手册正文，程序联网拉这份 | 手改 |
| `音游记录\<曲名>\*.json` | 音游模式传上来的成绩（一条一个文件） | 程序自动写 |
| `错误报告\*.json` | 程序没接住的异常（上报用，路径已脱敏） | 程序自动写 |

> 程序只认 `.mid` / `.midi` 当曲子，这些 json 不会被列进歌单。
> 增量更新的原理、发版流程、差分包传哪儿 —— 见项目里的 `docs/增量更新设计.md`。

## payload.json 怎么用（在线安装程序用的）

「在线安装程序」就是那个 **46 MB 的小 exe**：百度网盘下完整包太慢的话，用户下它就行。
它启动后先拉这份 `payload.json`，才知道「要下什么、下下来的东西对不对」：

* 里面写着每个版本（完全版 / 精简版）的**切片名、大小、sha256、下载地址前缀**；
* 切片放在本仓库 **Gitee Releases 的附件**里（`vX.Y.Z` 那个 Release），按 32 MB 一片 ——
  完全版 6 片、精简版 2 片（Gitee 单附件上限 100 MB，切小了断点续传代价也小）；
* 这个 json 跟 `version.json` / `notice.json` 一样放在仓库**根目录**、联网拉；
* 生成 / 上传：`python -X utf8 make_parts.py` → `python -X utf8 上传分片到Gitee.py --manifest`。
  手改容易跟切片对不上（大小 / sha256 是算出来的），别手改。

断点续传、校验、发版顺序的细节见项目里的 `docs/在线安装程序.md`。

## library.json 怎么用

这个文件夹里的 `library.json` 是**联网曲库的索引** —— 程序读它才知道仓库里有哪些
曲子、每首多大、叫什么名字。

> **不传也能用。** 程序发现仓库里没有索引文件，会直接问 GitHub
> 「这个仓库里有哪些文件」，把里面所有 `.mid / .midi` 列成歌单。所以
> `midi-music` 仓库现在这样（只有几个 midi）就能直接用，什么都不用做。

传它的好处：能带上**标题 / 作曲家**这些信息（不然标题就是文件名）、能写 `sha1`
校验下载完整性、仓库里混着别的东西时也不会被误当成曲子。

## 想传的话

1. 把 `library.json` **上传到 `midi-music` 仓库的根目录**（和 `鸟之诗.mid` 放一起，
   路径要和索引里 `file` 写的一模一样）；
2. 程序里填的曲库地址就是这一条（已经打包进 v1.15 / v1.15.1 了）：

   ```text
   https://raw.githubusercontent.com/xXjuanneysXx/midi-music/main/library.json
   ```

   raw 连不上时程序会**自动换 jsDelivr 镜像**再试一次：

   ```text
   https://cdn.jsdelivr.net/gh/xXjuanneysXx/midi-music@main/library.json
   ```

3. 提交完等一分钟左右（jsDelivr 有缓存），在程序里点「联网曲库」「刷新」就能看到两首曲子。

## 不想手动改？

程序里「联网曲库」→ 右下角「**上传 / 整理曲库…**」（令牌是内置在程序里的，
不用填任何东西；只下载的话更是用不着）：

* 传一首 midi：写进仓库，然后**按仓库里现有的文件重新生成** `library.json`
  （不会写着写着和仓库对不上）；
* 「按仓库现有文件重排索引」：不传新文件，只重排索引 —— 你手动往仓库里丢过文件，
  点一下就补齐了。

旁边那两个按钮用的是**程序里内置的令牌**，不用你填 —— 点一下就开始传，
传上去就等于同意把这首曲子开源分享。

> ⚠ 这个仓库是**公开的开源曲库**：传上去的东西所有人都能看见、能下载。

## 索引格式

```json
{
  "version": 1,
  "songs": [
    {"title": "鸟之诗", "artist": "", "file": "鸟之诗.mid",
     "size": 9031, "sha1": "7dcfc4619cb831b241bb9340cce0dc1892576496"}
  ]
}
```

* `file` 是**相对于索引文件**的路径（索引在仓库根目录，所以就写文件名）；
* `size` / `sha1` 用来校验下载下来的文件 —— 对不上会拒绝写入并告诉你。`sha1` 可以不写；
* 手写也行：程序只认 `file`，`title` 缺了就用文件名。
